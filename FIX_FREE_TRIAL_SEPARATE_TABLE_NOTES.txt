FREE TRIAL ACTIVATION FIX (V2)
================================

Root problem
------------
The previous implementation stored FREE inside the paid subscriptions table.
Older PostgreSQL/Neon databases restrict subscriptions.plan_id to:
  pro, premium, max

The serverless API attempted to ALTER old constraints during a request. That
migration could fail or race on Vercel, leaving the UI with the generic
"Unable to activate the free trial" error.

Permanent fix
-------------
1. FREE trials now use a dedicated free_trials table.
2. No paid-table constraint migration is required.
3. One row per user enforces one trial per Telegram account.
4. The 3-day start and expiry timestamps are created by PostgreSQL.
5. /api/auth/me reads both paid subscriptions and free trials.
6. Legacy FREE rows in subscriptions are still recognized.
7. Paid payment-history errors no longer roll back an activated subscription.
8. /api/db-status now reports freeTrialsReady and schemaVersion.

After deploying
---------------
Open:
  https://YOUR-DOMAIN/api/db-status

Expected response includes:
  "ok": true
  "freeTrialsReady": true
  "schemaVersion": "free-trials-v2"

Then log in with Telegram and start the free trial.
