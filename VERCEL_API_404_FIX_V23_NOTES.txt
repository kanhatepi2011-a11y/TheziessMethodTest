THEZIESS METHOD - VERCEL API 404 FIX V23

Problem
-------
The previous single-function build used api/[...route].js as a catch-all entrypoint.
On the deployed Vite project, requests such as /api/auth/telegram were not matched by
Vercel and returned the platform-level 404 NOT_FOUND page before the router code ran.

Fix
---
1. Replaced the wildcard entrypoint with one fixed function:

   api/router.js

2. Added this Vercel rewrite before all other rewrites:

   /api/:route*  ->  /api/router

   Vercel passes the captured route value through req.query.route. The router then
   dispatches it to the correct internal handler in server/routes/.

3. Updated vercel.json so only api/router.js is configured as a function.
4. Updated npm run cleanup-api to keep only api/router.js and remove old API files.

Result
------
- Vercel Serverless Function count: 1
- Existing public URLs remain unchanged.
- /api/auth/telegram, /api/auth/me, TikTok endpoints, Telegram webhook and all other
  existing routes continue to use their original URLs.

Important deployment steps
--------------------------
Run:

  npm run cleanup-api
  git add -A
  git commit -m "Fix Vercel API routing 404"
  git push origin main

On GitHub, api/ must contain only router.js. Delete api/[...route].js if it remains.
