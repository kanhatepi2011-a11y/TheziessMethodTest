TheZiess Method — Telegram Admin Bot V10 reliability fix

What changed
- The website now checks and registers the Telegram webhook automatically.
- The stable Vercel production URL is preferred over temporary preview URLs.
- The webhook URL includes a safe configuration version so token/secret changes
  trigger a correct webhook refresh.
- /ping, /id, /start and /help work without loading PostgreSQL first.
- Database code is loaded only when an admin requests database information.
- A database error is now shown inside Telegram instead of failing silently.
- /api/telegram/health shows the bot, webhook and configuration status without
  exposing tokens or secrets.
- TELEGRAM_WEBHOOK_SECRET and TELEGRAM_SETUP_KEY are now optional.
- BOT_TOKEN and a legacy Bot-API-shaped TELEGRAM_CLIENT_SECRET are supported as
  safe fallbacks, though TELEGRAM_BOT_TOKEN remains the recommended variable.

Required Vercel variables
- TELEGRAM_BOT_TOKEN
- TELEGRAM_ADMIN_IDS
- DATABASE_URL
- SESSION_SECRET

After deployment
1. Open the website once. It automatically connects the webhook.
2. Open /api/telegram/health and confirm status is connected.
3. Send /ping, then /id, then /admin to the Telegram bot.
